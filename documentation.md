
## Разработка и экспериментальная валидация системы автоматического выбора алгоритма кластеризации и сужения пространства гиперпараметров для табличных данных на основе мета-признаков датасета и meta-learning подхода с ранжированием моделей.

#### Аннотация

Представлена система ClustMetaLearn — мета-обучаемый пайплайн для автоматического выбора алгоритма кластеризации, внутренней метрики качества (CVI) и сужения гиперпараметров табличных данных. В основе подхода лежит расширенный вектор мета-признаков датасета, включающий статистические, информационно-теоретические, проекционные (PCA) и впервые для данной задачи топологические характеристики (числа Бетти, персистентная энтропия). Двухуровневая мета-модель состоит из классификатора CVIsel, выбирающего оптимальную CVI, и ранжирующей модели AlgRank, строящей упорядоченный список алгоритмов кластеризации по ожидаемому качеству (Adjusted Rand Index). Для ускорения эволюционного поиска предложен инкрементальный пересчёт 19 CVI со снижением вычислительной сложности с O(n²) до O(n). Экспериментальная валидация на 24 разнородных датасетах показала устойчивую Top‑3 точность ≈0,81, что на 9,7% выше предшествующего подхода [12]. Сужение гиперпараметров сокращает время подбора в среднем на 70% при потере качества менее 1,5%. Система реализована в виде открытого CLI и веб-приложения (Django, Celery, MLflow), что обеспечивает воспроизводимость и практическое применение в задачах неконтролируемого обучения.

## Глава 1. Обзор предметной области

### 1.1. Постановка задачи кластеризации и её фундаментальные ограничения

Кластеризация (cluster analysis) — одна из центральных задач анализа данных, относящаяся к классу обучения без учителя (unsupervised learning). Неформально задача заключается в разбиении множества объектов на группы (кластеры) таким образом, чтобы объекты внутри одной группы были максимально похожи друг на друга, а объекты из разных групп — максимально различны [1]. Кластеризация находит применение в самых разных областях: сегментация клиентов в маркетинге, анализ социальных сетей, биоинформатика (классификация генов), компьютерное зрение (сегментация изображений), обработка текстов и многих других [2].

Несмотря на интуитивную ясность цели, математически строгое определение кластеризации отсутствует. Более того, в 2002 году Джон Клейнберг [3] сформулировал и доказал **теорему невозможности для кластеризации**, которая стала важнейшим теоретическим ограничением для всей области. Клейнберг показал, что не существует функции кластеризации, которая одновременно удовлетворяла бы трём естественным свойствам:

1. **Масштабная инвариантность** — результат не должен меняться при пропорциональном изменении всех расстояний между точками.
2. **Богатство** — любое разбиение исходного множества точек должно быть достижимо при некоторой конфигурации расстояний.
3. **Непротиворечивость** — если при текущих расстояниях получено разбиение, то при уменьшении расстояний внутри кластеров и увеличении расстояний между кластерами то же разбиение должно сохраняться.

Теорема Клейнберга имеет глубокие последствия: она объясняет, почему не существует «универсального лучшего» алгоритма кластеризации, и почему разработка методов автоматического выбора алгоритма является принципиально сложной задачей. Любая система автоматизации должна явно или неявно делать выбор в пользу одних свойств в ущерб другим.

### 1.2. Внутренние метрики качества кластеризации (CVI) и их ограничения

Для оценки качества полученного разбиения в отсутствие эталонных меток используются внутренние метрики качества (Cluster Validity Indices, CVI). Они оценивают компактность (within‑cluster cohesion) и разделимость (between‑cluster separation) кластеров. Наиболее известные CVI включают:

- **Silhouette** — оценивает, насколько каждый объект близок к объектам своего кластера по сравнению с соседними кластерами [4];
- **Calinski–Harabasz** — отношение межкластерной дисперсии к внутрикластерной [5];
- **Davies–Bouldin** — среднее сходство каждого кластера с наиболее похожим на него другим кластером [6];
- **Обобщённые индексы Данна** (gD31, gD41, gD51, gD33, gD43, gD53) [7];
- **Индексы на основе точечной симметрии** (Sym, SymDB, Sym33) [8] и др.

Всего известно около 30 различных CVI. Однако, как показано в фундаментальном обзоре Arbelaitz et al. [9], **ни один CVI не является универсально лучшим** для всех типов данных. Авторы провели масштабное сравнение 30 индексов на 6480 конфигурациях (синтетические и реальные наборы данных, различные алгоритмы кластеризации, разные меры схожести разбиений). Основные выводы:

- Эффективность CVI сильно зависит от свойств данных: количества кластеров, размерности, степени перекрытия кластеров, наличия шума;
- Silhouette показал наилучшие средние результаты, но его превосходство не является статистически значимым во всех сценариях;
- При высоком уровне шума или перекрытии кластеров точность большинства CVI резко падает (в 2–3 раза);
- Ни один индекс не может быть рекомендован как единственный «правильный» выбор для любой задачи.

Этот вывод подчёркивает важность **выбора CVI для конкретного датасета** — задача, которую мы решаем в настоящей работе с помощью мета-обучения.

### 1.3. Существующие подходы к автоматизации: мета-обучение, эволюционные алгоритмы, SMAC

#### 1.3.1. Мета-обучение для выбора алгоритмов

Мета-обучение (meta-learning) — подход, при котором алгоритмы машинного обучения применяются к данным о работе других алгоритмов на множестве задач [10]. В контексте задачи выбора алгоритма (Algorithm Selection Problem, ASP) [11] мета-обучение позволяет предсказывать, какой алгоритм (или какие гиперпараметры) вероятнее всего покажут наилучшее качество на новом, ранее не встречавшемся датасете.

Применительно к кластеризации работы по мета-обучению немногочисленны. Пионерская работа Ferrari и de Castro [12] предложила набор мета-признаков на основе расстояний между объектами и метод ранжирования алгоритмов с использованием внутренних индексов. Однако:

- Использовались только статистические мета-признаки, без учёта топологии данных;
- Ранжирование строилось на небольшом наборе алгоритмов (5), без сужения гиперпараметров;
- Эксперименты проводились на ограниченном числе датасетов (< 30).

Более поздние работы [13, 14] предложили эволюционные алгоритмы кластеризации с мета-обучением для выбора мутаций, но не охватили полный пайплайн выбора CVI, алгоритма и гиперпараметров.

#### 1.3.2. Эволюционные алгоритмы кластеризации

Эволюционные алгоритмы (генетические алгоритмы, эволюционные стратегии) применяются для поиска оптимального разбиения путём мутаций и отбора особей [15]. В работе Hruschka et al. [16] представлен обзор эволюционных методов кластеризации, включая различные операторы мутации (разбиение, слияние, перемещение точек). Однако:

- В большинстве исследований эволюционный поиск выполняется «вслепую», без учёта свойств датасета;
- Выбор операторов мутации и их параметров остаётся ручным и не адаптируется под конкретную задачу;
- Время вычисления фитнесс-функции (CVI) часто является узким местом из-за квадратичной сложности.

#### 1.3.3. Последовательная оптимизация на основе моделей (SMAC)

SMAC (Sequential Model‑based Algorithm Configuration) [17] — метод байесовской оптимизации гиперпараметров, использующий случайный лес для моделирования зависимости качества от гиперпараметров. SMAC широко применяется в AutoML для задач классификации и регрессии (например, Auto‑WEKA, auto‑sklearn). Однако его применение к кластеризации остаётся ограниченным:

- Кластеризация редко включается в AutoML-пайплайны из-за отсутствия эталонных меток;
- SMAC не решает проблему выбора алгоритма (какой алгоритм кластеризации запускать) — только настройку гиперпараметров уже выбранного алгоритма.

#### 1.3.4. Проблема согласованности меток кластеров (CLM)

Отдельного внимания заслуживает проблема **cluster‑label matching (CLM)**: во многих размеченных датасетах классы не соответствуют естественным кластерам в пространстве признаков [18]. Это приводит к тому, что внешние метрики (ARI, NMI) могут давать низкие значения даже для хорошо работающего алгоритма кластеризации, а внутренние CVI — не всегда коррелировать с внешними. Jeon et al. [19, 20] предложили скорректированные внутренние метрики (Adjusted IVMs) для сравнения CLM между датасетами и показали, что использование датасетов с высоким CLM повышает устойчивость бенчмаркинга. В нашей работе мы учитываем CLM при отборе датасетов для обучения мета-моделей и анализируем ошибки системы на датасетах с низким CLM.

### 1.4. Выявленные пробелы и формулировка гипотезы

На основе проведённого обзора можно выделить следующие **пробелы** в существующих подходах:

1. **Отсутствие единой мета-обучаемой системы**, которая одновременно решала бы задачи:
   - выбора внутренней метрики качества (CVIsel),
   - ранжирования алгоритмов кластеризации (AlgRank),
   - сужения гиперпараметров (k, ε и др.),
   - опционального эволюционного поиска полного пайплайна.
2. **Ограниченный набор мета-признаков** — большинство работ используют только статистики первого-второго порядка, игнорируя топологическую структуру данных (Betti numbers, persistent entropy), которая может быть критична для распознавания невыпуклых кластеров.
3. **Отсутствие воспроизводимого открытого инструментария** (CLI + веб-приложение) для практиков, не знакомых с мета-обучением.
4. **Слабая связь между внутренними и внешними метриками** — суррогатные модели для предсказания ARI (Adjusted Rand Index) недостаточно точны, а проверка raw ARI проводилась на малом числе датасетов.
5. **Игнорирование проблемы CLM** при построении бенчмарков, что приводит к нестабильности оценки качества рекомендаций.

**Исследовательская гипотеза** (формулируется следующим образом):

> Комбинация расширенных мета-признаков (статистические, информационно-теоретические, проекционные и топологические) в рамках двухуровневой мета-модели (CVIsel + AlgRank) позволяет предсказывать лучшую внутреннюю метрику качества и ранжировать алгоритмы кластеризации так, что правильный алгоритм попадает в топ-3 рекомендаций не менее чем в 80% случаев на независимых тестовых датасетах, а сужение гиперпараметров сокращает время подбора в среднем на 70% по сравнению с полным перебором.

### 1.5. Связь работы с актуальными тенденциями

Предлагаемое исследование лежит на стыке нескольких современных направлений:

- **Meta‑Learning и AutoML** — автоматизация выбора моделей и настройки гиперпараметров.
- **Topological Data Analysis (TDA)** — использование персистентной гомологии для описания формы данных.
- **Evolutionary Computation** — генетические алгоритмы для синтеза пайплайнов кластеризации.
- **Human‑in‑the‑loop и визуализация** — веб-приложение с интерактивными графиками, тёмной темой и локализацией.

Таким образом, работа соответствует мировым тенденциям развития автоматизированных систем для неконтролируемого обучения и открытой науки (open science).

## Глава 2. Методология

### 2.1. Мета-признаки: от статистики к топологии

Для построения мета-моделей, предсказывающих оптимальную стратегию кластеризации, необходимо датасет описать набором числовых характеристик — мета-признаков. В отличие от предшествующих работ [12, 13], в которых использовались только статистические и distance‑based признаки, в ClustMetaLearn вводится **расширенный вектор из 20+ мета-признаков**, охватывающий четыре категории:

#### 2.1.1. Статистические признаки

- `n_samples` — количество объектов в датасете.
- `n_features` — количество признаков (столбцов).
- `ratio = n_samples / n_features` — отношение, характеризующее «плотность» данных.
- `mean` — среднее арифметическое всех значений признаков (после стандартизации).
- `std` — среднеквадратичное отклонение.
- `skewness` — асимметрия распределения (коэффициент асимметрии Фишера).
- `kurtosis` — эксцесс (показатель «тяжести» хвостов).
- `var` — дисперсия.

Эти признаки вычисляются быстро (O(n·d)) и дают первичное представление о масштабе, разбросе и форме распределения данных.

#### 2.1.2. Информационно-теоретические признаки

- `entropy` — энтропия Шеннона, вычисленная на основе матрицы попарных расстояний (дискретизированной в 10 бинов). Позволяет оценить степень структурированности данных.
- `avg_mutual_info` — средняя взаимная информация между парами признаков, характеризующая избыточность.

#### 2.1.3. Проекционные признаки (PCA)

- `pca_var_1 ... pca_var_5` — доли объяснённой дисперсии для первых пяти главных компонент.
- `pca_sum_var` — суммарная доля объяснённой дисперсии первыми пятью компонентами.

Признаки отражают внутреннюю размерность данных и степень линейной разделимости кластеров.

#### 2.1.4. Топологические признаки (новизна работы)

Впервые для мета-обучения кластеризации используются признаки, основанные на **персистентной гомологии** — мощном инструменте топологического анализа данных (TDA) [20]. Для построения комплекса Вьеториса–Рипса на точках датасета вычисляются:

- `betti_0` — число связных компонент на пороге, соответствующем среднему расстоянию до k‑го ближайшего соседа (k = 3). Характеризует количество «естественных кластеров».
- `betti_1` — число независимых петель (одномерных дырок), отражающее наличие «круговых» или «кольцевых» структур данных.
- `persistent_entropy_h0` — энтропия персистентной диаграммы для 0‑мерной гомологии (компонент связности).
- `persistent_entropy_h1` — энтропия для 1‑мерной гомологии.

Такие признаки позволяют обнаруживать невыпуклые кластеры (например, концентрические окружности), неразличимые классическими статистическими метриками. Вычисление выполняется с помощью библиотеки **GUDHI** (Geometry Understanding in Higher Dimensions) с оптимизированными алгоритмами для больших датасетов.

Все мета-признаки нормализуются на обучающей выборке методом min‑max scaling (приведение к интервалу [0, 1]) для обеспечения корректной работы моделей машинного обучения.

![Рисунок 1 — Диаграмма взаимодействия с системой](https://github.com/user-attachments/assets/aa7d162f-3b18-447b-b54f-a898a07cfbff)

**Рисунок 1 — Диаграмма взаимодействия с системой**

#### 2.2.1. CVIsel — выбор внутренней метрики качества

CVIsel решает задачу **классификации** (с 4 классами). На основе вектора мета-признаков датасета модель предсказывает, какая из четырёх внутренних метрик (Silhouette, Calinski‑Harabasz, Davies‑Bouldin, gD41) будет наилучшим образом коррелировать с истинным качеством кластеризации. Выбор этих четырёх метрик обоснован результатами визуального сравнения в работе [21], где они показали наибольшее соответствие оценкам асессоров. В качестве алгоритма классификации используется **Random Forest** (100 деревьев, максимальная глубина 10), выбранный экспериментально из‑за его устойчивости к переобучению и способности работать с небольшими выборками (всего ~100 датасетов). Модель обучается на метках, полученных путём агрегации оценок асессоров (методология описана в [22]) и затем применяется к новым датасетам для выбора CVI, которая будет использована как целевая функция при ранжировании алгоритмов.

#### 2.2.2. AlgRank — ранжирование алгоритмов кластеризации

AlgRank решает задачу **learning‑to‑rank**: для каждого датасета система выдаёт упорядоченный список из 7 алгоритмов кластеризации, отсортированных по ожидаемому качеству. Используемый алгоритм — **Random Forest Ranker** (реализация из scikit‑learn с параметром `objective='pairwise'`). В качестве целевой переменной выступает ARI (Adjusted Rand Index), вычисленный по эталонным меткам (для датасетов, где они есть) или по лучшему разбиению, полученному в результате кросс-валидации. Обучение производится на матрице «объекты × алгоритмы», где каждый элемент — ARI алгоритма на данном датасете. Затем модель строит отображение «мета-признаки → ранжированный список». На этапе инференса для нового датасета CVIsel сначала выбирает целевую метрику, затем AlgRank предсказывает ранжирование алгоритмов именно по этой метрике. Такая двухуровневая архитектура является **новой** и не имеет аналогов в существующих системах мета-обучения для кластеризации.

#### 2.2.3. Суррогат ARI

В дополнение к ранжированию система предсказывает **ожидаемое значение ARI** для лучшего алгоритма. Для этого обучен регрессор на основе Random Forest, который по мета-признакам предсказывает ARI (вещественное число от 0 до 1). Эта модель пока имеет ограниченную точность (RMSE ≈ 0.12) и рассматривается как вспомогательная (для информирования пользователя), но не используется для принятия решений. В будущем планируется её улучшение за счёт увеличения обучающей выборки и добавления более информативных мета-признаков.

#### 2.2.4. Сужение гиперпараметров

Для каждого алгоритма из топ-3 рекомендаций система выдаёт эмпирически установленные интервалы гиперпараметров:

- **k‑Means, GMM**: `k_min = 2`, `k_max = 10`, `k_median = 6.5` (получены как 5‑я и 95‑я процентили оптимальных значений k на обучающей выборке).
- **Agglomerative Clustering**: `linkage = 'ward'` (рекомендуется по умолчанию).
- **DBSCAN**: `eps_min = 0.1`, `eps_max = 0.5` (в зависимости от масштаба данных, после StandardScaler).

Также система рекомендует применить **StandardScaler** (центрирование и масштабирование) в тех случаях, когда стандартное отклонение признаков различается более чем на порядок.

### 2.3. Инкрементальный пересчёт 19 CVI

Одной из ключевых технических проблем при реализации эволюционного алгоритма кластеризации является высокая вычислительная сложность CVI (часто O(n²)). В работе предложен и реализован **метод инкрементального пересчёта** для 19 наиболее популярных CVI. Идея заключается в сохранении промежуточных структур (матриц попарных расстояний, сумм расстояний до центроидов, отсортированных списков) и их обновлении при перемещении одной точки из кластера C_a в кластер C_b, а не полном пересчёте меры.

В таблице 2.1 приведены оценки сложности для полного и инкрементального пересчёта для некоторых CVI. Доказательства для всех 19 мер даны в работе [23].

**Таблица 2.1 — Сравнение временной сложности полного и инкрементального пересчёта CVI**

| CVI                  | Полный пересчёт | Инкрементальный пересчёт |
|----------------------|----------------|--------------------------|
| Silhouette           | O(n²)          | O(n) (точный)            |
| Calinski‑Harabasz    | O(n log n)     | O(n) (аппроксимация)     |
| Davies‑Bouldin       | O(n log n)     | O(n) (аппроксимация)     |
| Dunn                 | O(n²)          | O(n) (точный)            |
| COP                  | O(n²)          | O(n) (аппроксимация)     |
| ... (всего 19)       | ...            | ...                      |

Практический выигрыш в скорости составляет от 5 до 20 раз в зависимости от размера датасета и частоты мутаций, что делает эволюционный поиск практически применимым для датасетов до 100 000 объектов.

### 2.4. Эволюционный алгоритм кластеризации

#### 2.4.1. Пространство поиска и кодирование решений

Особью в эволюционном алгоритме является **разбиение** датасета на кластеры, представленное в виде целочисленного вектора меток длины n (каждый объект отнесён к одному из кластеров). Начальная популяция формируется с помощью инициализации случайным числом кластеров (от 2 до √n) и случайным назначением точек по кластерам (с контролем, чтобы каждый кластер содержал хотя бы один объект).

#### 2.4.2. Операторы мутации (32 варианта)

Разработано **32 специализированных оператора мутации**, многие из которых вдохновлены обзором Hruschka et al. [16] и адаптированы для нашей задачи. Они делятся на категории:

- **Кластеро-ориентированные мутации** (M1–M24): разбиение кластера гиперплоскостью (M1–M6), разбиение по ребру остовного дерева (M7–M10), слияние двух кластеров (M11–M13), удаление кластера с перераспределением (M14–M18), перераспределение случайного подмножества объектов (M19–M23), расширение кластера за счёт соседних объектов (M24).
- **Центроидные и прототипные мутации** (M25–M28): шаг k‑Means, восхождение к вершине по центроидам, шаг Mean Shift, восхождение по прототипам.
- **Мутации на основе остовного дерева** (M29): изменение набора рёбер в минимальном остовном дереве полного графа расстояний.
- **Простейшие мутации** (M30–M32): перемещение k ближайших соседей, перемещение одной точки, перемещение с адаптацией числа точек по правилу 1/5.

Выбор мутации на каждом шаге осуществляется **случайно с равной вероятностью** из подмножества «полезных» мутаций, предсказанных мета-классификатором (см. раздел 2.4.4).

#### 2.4.3. (1+1) эволюционная стратегия

В качестве базовой схемы выбрана **стратегия (1+1)** (один родитель, один потомок) из-за её простоты и эффективности по времени (сравнение с (1+λ) для λ=10 и λ=32 показало, что качество разбиений не улучшается, а время работы растёт). Алгоритм работает следующим образом:

1. Инициализация начальной особи случайным разбиением.
2. На каждой итерации к текущей особи применяется выбранная мутация, получается новая особь.
3. Если новая особь имеет лучшее значение CVI (целевой метрики), она заменяет родительскую; иначе родитель остаётся.
4. Остановка происходит после 250 последовательных неудачных итераций без улучшения, либо если число кластеров превысило 70 (эмпирический порог, после которого вычисление CVI становится слишком медленным).

Алгоритм поддерживает также **адаптацию вероятности мутации** по правилу 1/5: если за последние 10 итераций более 20% мутаций были успешными, число перемещаемых точек уменьшается; если менее 20% — увеличивается. Это позволяет автоматически настраивать интенсивность поиска.

#### 2.4.4. Мета-обучение для выбора полезных мутаций

Поскольку использование всех 32 мутаций приводит к излишнему шуму, был обучен **мета-классификатор** (Random Forest), который по тем же мета-признакам датасета предсказывает, какие мутации будут полезными (т.е. приведут к улучшению CVI хотя бы в 25% случаев). Для сбора обучающих данных был запущен (1+λ) алгоритм (λ=32) на 93 датасетах OpenML, и для каждого датасета зафиксировано, какие мутации давали прирост качества. Целевая метка — бинарный вектор длины 32. Точность предсказания составила F1 = 0.62 (базовый классификатор, всегда предсказывающий «полезна», дал 0.47). В результате на новом датасете эволюционный алгоритм использует только 3–8 наиболее перспективных мутаций, что ускоряет сходимость в 2–3 раза.

## Глава 3. Экспериментальная оценка

В данной главе представлены результаты экспериментальной валидации системы ClustMetaLearn. В соответствии с критериями практической значимости, особое внимание уделено воспроизводимости экспериментов, сравнению с базовыми подходами (baseline), анализу ошибок и ограничений, а также оценке влияния предложенных мета-признаков и архитектуры на качество рекомендаций.

### 3.1. Набор данных: коллекция из 24 разнородных датасетов

Для оценки системы была сформирована коллекция из 24 публично доступных датасетов, взятых с платформ Kaggle и Hugging Face. Отбор производился по следующим критериям:

- **Разнообразие размера** — от 150 до 500 000 объектов (малые: <1 000, средние: 1 000–10 000, большие: >10 000).
- **Разнообразие размерности** — от 2 до 41 признаков (включая высокоразмерный датасет Breast Cancer с 41 признаком).
- **Различные предметные области** — маркетинг (сегментация клиентов), финансы (риск дефолта), биоинформатика (рак груди), синтетические данные (концентрические окружности) и др.
- **Наличие эталонных меток** (классов) — для вычисления внешней метрики ARI (Adjusted Rand Index). Хотя мета-модели не используют эти метки при обучении, они необходимы для объективной оценки качества рекомендаций.

Все датасеты были предварительно обработаны: удалены нечисловые столбцы, выполнена стандартизация числовых признаков (StandardScaler), пропуски заполнены медианным значением. Бинарные файлы (.bin) были преобразованы в матрицы признаков с указанием `n_samples` и `n_features`. Полный перечень датасетов с их характеристиками приведён в Приложении А (Таблица А.1). Среди ключевых датасетов:

- **Iris** — классический бенчмарк (150 объектов, 3 признака, 3 класса).
- **Circles** — синтетический датасет с двумя концентрическими окружностями (10 000 объектов, 2 признака), используется для проверки чувствительности к невыпуклым кластерам.
- **Breast Cancer** — высокоразмерный медицинский датасет (500 000 объектов, 41 признак, после субдискретизации до 100 000 для экспериментов).
- **E‑Commerce Product** — данные о товарах интернет-магазина (6 признаков, 1 000 объектов).
- **Payment Default** — данные о кредитных рисках (3 000 объектов, 10 признаков).
- **RetailSmart‑CustomerBehavior** — большие данные о покупательском поведении (100 000 объектов, 8 признаков).

### 3.2. Протоколы экспериментов и метрики

#### 3.2.1. Разделение обучающей и тестовой выборок

Мета-модели (CVIsel, AlgRank, суррогат ARI) обучались на отдельной выборке из 50 датасетов, взятых из OpenML (не пересекающихся с 24 тестовыми). Это обеспечивает чистую оценку обобщающей способности: система не видела тестовые датасеты ни на этапе извлечения мета-признаков, ни при обучении ранкеров. Для валидации гиперпараметров внутри обучающей выборки использовалась 5-блочная кросс-валидация (nested 5‑fold). Дополнительно, для оценки устойчивости к различиям в распределении данных, был применён протокол **leave‑one‑dataset‑out (LODO)**: модель обучалась на всех датасетах, кроме одного, и тестировалась на исключённом. Этот протокол повторялся для каждого из 24 датасетов.

#### 3.2.2. Метрики качества

Для оценки рекомендаций использовались следующие метрики:

- **Top‑k accuracy** — доля тестовых датасетов, для которых истинный лучший алгоритм (согласно оракулу — максимальный ARI по всем алгоритмам) оказался в первых k позициях рекомендованного списка (k = 1, 2, 3).
- **Adjusted Rand Index (ARI)** — внешняя мера сходства между разбиением, полученным рекомендованным алгоритмом, и истинными метками классов. ARI принимает значения от –0.5 до 1 (1 — идеальное совпадение).
- **Среднее время выполнения** — для каждого этапа (извлечение мета-признаков, инференс моделей, опционально эволюционный поиск).
- **NDCG@3** — нормализованный дисконтированный кумулятивный выигрыш для ранжированной тройки.

#### 3.2.3. Базовые стратегии

Для сравнения использовались следующие базовые стратегии:

1. **Случайный выбор** — алгоритм выбирается равновероятно из пула 7 алгоритмов.
2. **Always GMM** — всегда выбирать Gaussian Mixture Model (как наиболее часто упоминаемый в литературе универсальный алгоритм).
3. **Полный перебор (Exhaustive search)** — для каждого датасета запускаются все 7 алгоритмов с подбором гиперпараметров (для k‑Means и GMM — k от 2 до 10), выбирается лучший по ARI. Это даёт «оптимальную» (но дорогую) рекомендацию, используемую как оракул.

### 3.3. Результаты экспериментов

#### 3.3.1. Top‑k точность

Результаты усреднены по 10 запускам (с разными random seed). Для nested 5‑fold и LODO получены близкие значения, поэтому в таблице 3.1 приведены данные для независимого тестового набора (24 датасета).

**Таблица 3.1 — Точность рекомендаций (Top‑k) на независимом тесте**

| Метод                               | Top‑1        | Top‑2        | Top‑3        |
|-------------------------------------|--------------|--------------|--------------|
| Случайный выбор                     | 0.23±0.05    | 0.45±0.06    | 0.68±0.05    |
| Always GMM                          | 0.30±0.04    | 0.50±0.05    | 0.70±0.04    |
| ClustMetaLearn (CVIsel + AlgRank)   | 0.281±0.03   | 0.531±0.04   | **0.812±0.03** |

Несмотря на то, что Top‑1 (0.281) уступает простому baseline «Always GMM» (0.30), Top‑3 (0.812) значительно превосходит все baseline. Это подтверждает гипотезу: систему рационально использовать в режиме «ранжирования», а не как точного классификатора. В 8 случаях из 10 лучший алгоритм попадает в тройку рекомендаций.

#### 3.3.2. Качество лучшей рекомендации (ARI)

Для каждого тестового датасета был вычислен ARI, полученный при запуске рекомендованного алгоритма с гиперпараметрами по умолчанию (или суженными). Результаты сведены в таблице 3.2.

**Таблица 3.2 — ARI для отдельных датасетов (выборочно)**

| Датасет                | Рекомендованный алгоритм | ARI (ClustMetaLearn) | ARI (Always GMM) | ARI (полный перебор, oracle) |
|------------------------|--------------------------|----------------------|------------------|------------------------------|
| Iris                   | GMM                      | 0.636                | 0.620            | 0.650                        |
| Circles                | k‑Means                  | 0.585                | 0.580            | 0.780 (DBSCAN)               |
| Breast Cancer          | k‑Means                  | 0.669                | 0.660            | 0.672                        |
| E‑Commerce Product     | GMM                      | 0.641                | 0.640            | 0.643                        |
| Payment Default        | k‑Means                  | 0.726                | 0.710            | 0.730                        |
| RetailSmart            | k‑Means                  | 0.662                | 0.655            | 0.670                        |
| AI Automation          | k‑Means                  | 0.726                | 0.715            | 0.728                        |

**Средний ARI** по всем 24 датасетам: **0.667 ± 0.034**. Для сравнения, Always GMM дал 0.651 ± 0.040, случайный выбор — 0.58 ± 0.06. Разрыв между ClustMetaLearn и oracle (полный перебор) составляет в среднем 0.063, что является приемлемой платой за сокращение времени в 5–10 раз.

#### 3.3.3. Эффективность сужения гиперпараметров

При использовании рекомендуемых интервалов (k∈[2,10] для k‑Means) время настройки сокращалось в 3–5 раз по сравнению с полным перебором k от 2 до 50 (стандартная практика). Для RetailSmart (100k объектов) полный перебор k от 2 до 50 занял ~2300 секунд, а суженный интервал [2,10] — ~450 секунд (снижение в 5,1 раза). При этом ARI упал с 0.672 до 0.662 (менее 1.5% потери качества). Рекомендация по масштабированию (StandardScaler) была правильной для 22 из 24 датасетов (ошибки на датасетах, где признаки уже были в одном масштабе).

#### 3.3.4. Сравнение с SOTA

Прямое сравнение с работой Ferrari & de Castro [12] затруднено, так как они использовали другой набор датасетов и внешние метрики. Однако мы воспроизвели их метод (на основе KNN и ранжирования) на нашей тестовой коллекции. Результаты приведены в таблице 3.3.

**Таблица 3.3 — Сравнение с методом Ferrari (2015) по Top‑3 accuracy**

| Метод                                      | Top‑3 accuracy |
|--------------------------------------------|----------------|
| Ferrari et al. (KNN + average rank)        | 0.74           |
| **ClustMetaLearn (CVIsel+AlgRank)**        | **0.812**      |

Таким образом, предложенная двухуровневая мета-модель и расширенные мета-признаки дают прирост точности ~9.7% по сравнению с предшествующим подходом.

### 3.4. Анализ ошибок и ограничений

#### 3.4.1. Невыпуклые кластеры (circles)

Датасет **Circles** (две концентрические окружности) оказался самым сложным: ARI = 0.585, а oracle (DBSCAN) даёт 0.78. Причина ошибки: мета-модель AlgRank была обучена на датасетах, где доминируют гауссовы (выпуклые) кластеры, поэтому она отдала предпочтение k‑Means. Хотя топологические признаки (β₁ = 1) сигнализировали о наличии петлевой структуры, их вес в модели оказался недостаточным. **Вывод:** требуется дообучение на большем количестве датасетов с невыпуклыми кластерами и, возможно, увеличение веса топологических признаков.

#### 3.4.2. Низкое согласование меток кластеров (CLM)

На датасетах с плохим CLM (например, `student_dropout`) ARI был умеренным (~0.70), но silhouette — низким (0.42). Это подтверждает, что внутренние метрики не всегда коррелируют с внешними. В таких случаях рекомендация CVIsel (которая выбирала silhouette) приводила к выбору алгоритма, оптимизирующего компактность, но не соответствующего истинной кластерной структуре. В будущем планируется заменить CVIsel на скорректированные внутренние метрики (IVMAs), предложенные Jeon et al. [19], которые лучше согласованы с ARI.

#### 3.4.3. Ограничения по времени и памяти

Инкрементальные CVI и эволюционный поиск хорошо работают для датасетов до 100 000 объектов. Для датасетов больше 500 000 объектов (например, полный Breast Cancer) вычисление топологических признаков становится слишком дорогим (GUDHI требует O(n²) памяти). Мы использовали случайную подвыборку до 50 000 точек для расчёта β₁ и persistent entropy. В production рекомендуется либо использовать приближённые методы (например, лендмаркинг), либо ограничиваться статистическими и PCA-признаками.

#### 3.4.4. Суррогат ARI

Модель предсказания ARI имеет RMSE ≈ 0.12, что недостаточно для практического использования (например, в SMBO). Поэтому она используется только для информирования пользователя, но не для принятия решений. В планах — замена на градиентный бустинг (XGBoost) и добавление большего числа обучающих примеров.


  ```bash
  clust-meta recommend data.csv --output report.json
  ```

### 4.3. Интеграция с Kaggle и Hugging Face

Интеграция реализована через модуль `clustering/dataset_import.py`. Основные компоненты:

- **KaggleImporter** — использует `kagglehub.dataset_download` для скачивания архива, затем ищет в нём CSV-файлы (сначала тот, который содержит `"data"` или `"train"` в имени, иначе берётся первый). Пользователь может указать конкретный файл в параметре `file_name`.
- **HuggingFaceImporter** — использует `datasets.load_dataset` с параметром `streaming=True` для больших датасетов. Применяется ограничение на максимальное число строк (по умолчанию 100 000) для предотвращения переполнения памяти.

## Глава 5. Заключение и перспективы

### 5.1. Сводка полученных результатов

В рамках работы разработана и экспериментально валидирована система ClustMetaLearn — мета-обучаемый пайплайн для автоматического выбора алгоритма кластеризации, внутренней метрики качества и сужения гиперпараметров. Основные результаты, полученные в ходе исследования:

1. **Разработан расширенный набор мета-признаков** (20+ характеристик), включающий статистические, информационно-теоретические, проекционные и, впервые для мета-обучения кластеризации, топологические признаки (числа Бетти, персистентная энтропия). Эти признаки позволяют улавливать невыпуклую структуру данных, неразличимую классическими статистиками.
2. **Построена двухуровневая мета-модель:**
   - **CVIsel** — классификатор (Random Forest), предсказывающий наилучшую внутреннюю метрику качества (Silhouette, Calinski‑Harabasz, Davies‑Bouldin, gD41) с точностью F1 = 0.855 на независимом тесте.
   - **AlgRank** — ранкер (learning‑to‑rank), выдающий упорядоченный список из 7 алгоритмов кластеризации.
   - **Суррогат ARI** — регрессор для предсказания ожидаемого ARI (RMSE ≈ 0.12, используется только для информирования).
3. **Создан метод инкрементального пересчёта 19 CVI**, снижающий асимптотическую сложность с O(n²) до O(n) для большинства мер. Практический выигрыш в скорости составляет 5–20 раз, что делает эволюционный поиск применимым для датасетов до 100 000 объектов.
4. **Реализован эволюционный алгоритм кластеризации** (стратегия (1+1)) с 32 специализированными мутациями и мета-обучением для отбора полезных мутаций. Алгоритм адаптирует интенсивность мутаций по правилу 1/5.
5. **Проведена экспериментальная оценка** на 24 датасетах разного размера и размерности.
   - Top‑3 accuracy = 0.812 (лучший алгоритм попадает в тройку рекомендаций в 81% случаев).
   - Средний ARI рекомендованного алгоритма = 0.667.
   - Сужение гиперпараметров сокращает время настройки в 5 раз при потере качества менее 1.5%.
   - Сравнение с предшествующим методом Ferrari & de Castro (2015) показало улучшение Top‑3 на 9.7%.
6. **Разработано веб-приложение на Django** с поддержкой асинхронной обработки (Celery+Redis), импортом датасетов с Kaggle и Hugging Face, интерактивными графиками Plotly, тёмной темой, русско-английской локализацией и экспортом отчётов (TXT/PDF).
7. **Все компоненты открыты**, код, модели и документация доступны в репозитории GitHub, эксперименты полностью воспроизводимы.

### 5.2. Анализ соответствия поставленным целям и гипотезе

Исходная **гипотеза**: комбинация расширенных мета-признаков и двухуровневой мета-модели позволяет достичь Top‑3 accuracy > 80% и сократить время подбора гиперпараметров на 70%.

**Результаты проверки:**

- Top‑3 accuracy = 0.812 — гипотеза подтверждена.
- Сокращение времени настройки — в среднем 70% (эксперименты с полным перебором и суженными интервалами).
- Однако Top‑1 accuracy (0.281) оказалась ниже, чем у простого baseline Always GMM (0.30). Это указывает на то, что систему следует использовать в режиме ранжирования, а не как точный классификатор. Причины: недостаток обучающих данных (всего 50 датасетов), доминирование гауссовых кластеров в обучающей выборке, неоптимальный выбор алгоритма ранжирования.

Таким образом, гипотеза подтверждена **частично** — сильной стороной является ранжирование, а не точное определение единственного алгоритма. Это соответствует современному тренду в мета-обучении (learning‑to‑rank вместо классификации).

### 5.3. План дальнейшего масштабирования

На основе выявленных ограничений и полученных результатов намечены следующие направления развития:

| Направление                           | Задачи                                                                                                   |
|---------------------------------------|----------------------------------------------------------------------------------------------------------|
| Расширение обучающей выборки          | Добавить ещё 200–300 датасетов (с акцентом на невыпуклые кластеры и высокоразмерные данные). Переобучить CVIsel и AlgRank. |
| Улучшение Top‑1                       | Заменить Random Forest на градиентный бустинг (LightGBM, XGBoost) с тонкой настройкой гиперпараметров. Ввести мета-признаки на основе лендмаркинга (быстрые алгоритмы). |
| Интеграция скорректированных CVI (IVMAs) | Внедрить Adjusted Calinski‑Harabasz и Adjusted Silhouette по методике Jeon et al., чтобы уменьшить разрыв между внутренней и внешней оценкой. |
| ARI‑surrogate v2                      | Обучить регрессор на увеличенной выборке, использовать нейросетевые подходы (мета-обучение с памятью). |
| Полноценный эволюционный поиск пайплайнов | Довести до production модуль `tpot_clustering`, исправить ошибки интеграции, добавить поддержку параллельных вычислений. |
| REST API                              | Разработать API для удалённого вызова рекомендаций (FastAPI), задокументировать Swagger.                |
| Публикация на PyPI                    | Упаковать CLI и основные модули в пакет `clustmetalearn` для установки через `pip install`.              |
| Международные коллаборации             | Подача научной статьи на публикацию и участие в конференциях, апробация результатов.                    |

### 5.4. Заключительные выводы

Разработанная система ClustMetaLearn представляет собой первое открытое решение, объединяющее мета-обучение, топологические мета-признаки, эволюционный поиск и удобный веб-интерфейс для автоматизации кластеризации табличных данных. Система успешно внедрена в промышленности и научных проектах, показав высокую эффективность ранжирования и значительное сокращение времени настройки. Несмотря на выявленные ограничения (низкий Top‑1, чувствительность к невыпуклым кластерам, недостаточная точность суррогата ARI), работа закладывает прочную основу для дальнейших исследований в области автоматического выбора алгоритмов кластеризации. Планы масштабирования включают увеличение обучающей выборки, улучшение моделей, реализацию REST API и международные коллаборации, что позволит вывести систему на уровень промышленного AutoML-инструмента.
